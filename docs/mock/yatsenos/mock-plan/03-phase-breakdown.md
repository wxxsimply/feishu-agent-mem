# 阶段议题与决策拆解

## Phase 0: 基础设施搭建 (W1-W2, 03/02-03/13)

### 议题 0.1: 开发环境统一
- **背景**: 团队成员使用不同操作系统，需要统一开发环境
- **决策 0.1.1**: 选择 WSL2 + Ubuntu 24.04 作为统一开发环境（vs 原生 Linux vs macOS）
- **决策 0.1.2**: 确定 Rust nightly 工具链版本
- **决策 0.1.3**: 统一 IDE 配置（VSCode + rust-analyzer + CodeLLDB）

### 议题 0.2: Rust 语言培训
- **背景**: 部分成员 Rust 经验不足
- **决策 0.2.1**: 安排一次 Rust 快速上手分享会（由 P1 主讲）
- **决策 0.2.2**: 完成实验 0x00 的 Rust 编程练习作为入门

### 议题 0.3: 项目初始化
- **背景**: 需要建立代码仓库和 CI 流程
- **决策 0.3.1**: 使用 Git 管理代码，采用 trunk-based 开发模式
- **决策 0.3.2**: 配置 GitHub Actions CI 流水线
- **决策 0.3.3**: 确定分支命名和 commit message 规范

### 议题 0.4: UEFI 环境验证
- **背景**: 需要确认 QEMU + OVMF 环境可以正常工作
- **决策 0.4.1**: 确认 QEMU 版本和启动参数
- **决策 0.4.2**: 验证 UEFI Shell 可以正常启动
- **决策 0.4.3**: 编写并运行第一个 UEFI Hello World 程序

## Phase 1: 引导加载器 (W2-W4, 03/09-03/27)

### 议题 1.1: 内核 ELF 编译配置
- **背景**: 内核需要编译为 ELF 格式，需要配置编译目标和链接脚本
- **决策 1.1.1**: 确定编译目标为 x86_64-unknown-none
- **决策 1.1.2**: 配置链接脚本，确定内核入口地址 0xffffff0000000000
- **决策 1.1.3**: 确认各段 4KB 对齐策略

### 议题 1.2: Bootloader 实现
- **背景**: 需要在 UEFI 环境中加载并跳转到内核
- **决策 1.2.1**: 加载配置文件和内核 ELF 的流程设计
- **决策 1.2.2**: Cr0 寄存器写保护禁用方案
- **决策 1.2.3**: 内核段映射策略（代码段、数据段、BSS 段的权限设置）
- **决策 1.2.4**: exit_boot_services 和 jump_to_entry 的实现方式

### 议题 1.3: 串口驱动实现
- **背景**: 需要实现 uart16550 驱动用于日志输出
- **决策 1.3.1**: SerialPort 结构体设计（是否使用 Const Generics）
- **决策 1.3.2**: 互斥锁保护方案（spin::Mutex + Once）
- **决策 1.3.3**: 日志系统接入（log crate + 自定义 Logger）

### 议题 1.4: 调试环境搭建
- **背景**: 需要 GDB + gef 进行内核调试
- **决策 1.4.1**: GDB 调试流程确认
- **决策 1.4.2**: .gdbinit 配置文件编写
- **决策 1.4.3**: VSCode 调试配置（可选）

**冲突点**: 议题 1.2.3 - P1 认为直接映射即可，P3 认为应该精细控制每段权限。争论 2 天后采用 P2 的折中方案。

- **决策 2.2.3**: 中断向量和 IRQ 常量定义

### 议题 2.3: APIC 初始化
- **背景**: 需要启用基于 APIC 的中断

### 议题 2.4: 串口输入驱动
- **背景**: 需要实现串口的输入能力
- **决策 2.4.1**: 串口输入中断处理函数设计

## Phase 3: 进程调度引擎 (W6-W8, 04/06-04/24)

### 议题 3.1: 进程模型设计
- **背景**: 需要确定进程模型
- **决策 3.1.1**: Linux 式进程模型（进程也是调度单位）vs Windows 式（线程是调度单位）
- **决策 3.1.2**: PCB 结构体设计（Process + ProcessInner）
- **决策 3.1.3**: ProcessId 的生成策略（复用 lab0 的 UniqueId 方案）

### 议题 3.2: 进程上下文切换
- **背景**: 需要实现进程切换时的上下文保存和恢复
- **决策 3.2.1**: 通用寄存器保存策略（全部保存 vs 按调用约定）
- **决策 3.2.2**: 中断上下文与进程上下文的衔接
- **决策 3.2.3**: as_handler 宏的实现

### 议题 3.3: 内核栈分配
- **背景**: 每个进程需要独立的内核栈
- **决策 3.3.1**: 内核栈大小选择
- **决策 3.3.2**: 栈空间分配方式

### 议题 3.4: FIFO 调度器实现
- **背景**: 需要实现基本的调度器
- **决策 3.4.1**: 调度器数据结构（就绪队列实现）
- **决策 3.4.2**: 时钟中断触发调度的流程
- **决策 3.4.3**: 进程状态转换（Running/Ready/Blocked/Terminated）

### 议题 3.5: 缺页异常处理
- **背景**: 需要实现进程的栈增长
- **决策 3.5.1**: 缺页异常处理流程
- **决策 3.5.2**: 栈增长策略（按需分配 vs 预分配）

**冲突点**: 议题 3.1.1 - P2 和 P3 激烈争论。P2 认为 Linux 式更简洁，P3 认为应该参考 Windows NT 的设计。争论 3 天，最终 P1 决定用 Linux 式（更简单）。
