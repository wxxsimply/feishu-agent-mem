# 群聊消息设计

## 1. 消息类型与比例

### 1.1 消息分类

| 消息类型 | 比例 | 示例 |
|---------|------|------|
| 技术讨论 | 40% | 方案分析、代码问题、调试经验 |
| 决策沟通 | 15% | 投票、方案选择、任务分配 |
| 进度同步 | 15% | "我这边搞定了"、"还在做"、"遇到问题" |
| 代码审查 | 10% | PR review、bug 报告、代码建议 |
| 闲聊废话 | 15% | 吐槽、段子、约饭、分享新闻 |
| 通知公告 | 5% | deadline 提醒、会议通知、文档更新 |

### 1.2 消息长度分布

| 消息长度 | 比例 | 典型场景 |
|---------|------|---------|
| 1-5 字 | 25% | "嗯"、"行"、"好的"、"+1" |
| 6-20 字 | 35% | "这个我来吧"、"PR 提了"、"测试没过" |
| 21-50 字 | 25% | 技术问题描述、进度更新 |
| 50-100 字 | 10% | 详细技术分析、方案说明 |
| 100+ 字 | 5% | 长篇技术讨论、会议纪要摘要 |

## 2. 消息模板库

### 2.1 技术讨论模板

**问题提出型**:
```
"有人遇到过 [具体问题] 吗？"
"[功能名] 这块怎么实现比较好？我有两个方案..."
"请教一下，[技术问题] 是什么原因？"
```

**方案讨论型**:
```
"我倾向于用 [方案A]，原因是..."
"你这个方案有个问题——[具体问题]"
"可以参考 [资料/论文] 的做法"
"我觉得两种方案各有优劣——A 的优势是...，B 的优势是..."
```

**问题解决型**:
```
"搞定了，问题是 [原因]，解决方法是 [方案]"
"终于调通了！"
"我调试了一下午，发现是 [bug 原因]"
```

### 2.2 决策沟通模板

**投票型**:
```
"大家投票——方案A 扣 1，方案B 扣 2"
"同意这个方案的请扣 +1"
"还有人有不同意见吗？没有的话就这样定了"
```

**任务分配型**:
```
"[任务名] 谁来负责？@[某人] 你对这块比较熟"
"这个我来吧"
"@所有人 这个阶段的任务分配如下..."
```

**确认型**:
```
"行，就这样定了"
"没问题"
"收到"
"好，那我这边按这个方案来"
```

### 2.3 进度同步模板

**完成型**:
```
"我这边搞定了"
"[功能名] 完成了，PR 已提交"
"测试通过了"
```

**进行中型**:
```
"还在做，预计明天完成"
"做了一半，遇到了点问题"
"这个比预想的复杂，需要多两天"
```

**阻塞型**:
```
"被 [问题] 卡住了，有人能帮忙看看吗？"
"这个依赖 [另一个功能]，得等那边先完成"
"我这边环境出了问题，需要 [某人] 帮忙看看"
```

### 2.4 闲聊废话模板

**吐槽型**:
```
"食堂的饭越来越难吃了"
"又加班..."
"这个 bug 改了一天了"
"Rust 的编译错误信息也太长了吧"
```

**分享型**:
```
"看到一篇不错的文章——[链接]"
"这个库挺有意思的"
"转发一个技术段子..."
```

**社交型**:
```
"周末愉快~"
"有人一起吃饭吗？"
"考试快到了，大家复习得怎么样？"
"恭喜 @[某人] 搞定了 [功能]！"
```

## 3. 冲突场景设计

### 3.1 技术方案冲突

**场景: ELF 加载方式争论 (Phase 1)**

```
赵一帆: 我觉得 load_segment 的映射不应该用 4K 粒度，应该用 2M 大页
林晓薇: 2M 大页的话权限控制就不够精细了，代码段和数据段要分开映射
赵一帆: 但是 4K 映射的话页表开销太大了
陈卓远: 先用 4K 吧，后面性能有问题再优化
赵一帆: 行吧，不过我觉得这个后面肯定要改
林晓薇: 我同意先用 4K，稳妥一些
```

**场景: 进程模型争论 (Phase 3)**

```
赵一帆: 我觉得应该参考 Windows NT 的设计，线程作为调度单位
林晓薇: 但是 Linux 式的更简单，对我们这个实验来说够用了
赵一帆: 简单不等于正确，线程和进程分离才是正道
林晓薇: 我们的时间有限，先实现最简单的方案
赵一帆: 那后面想改就难了
陈卓远: 先用 Linux 式，快速出成果，后面有时间再重构
赵一帆: ...
赵一帆: 行吧
```

### 3.2 代码质量冲突

**场景: 错误处理分歧 (Phase 6)**

```
周子涵: @李沐阳 你这个 ATA 驱动的错误处理呢？全是 unwrap
李沐阳: 能跑就行
周子涵: 不行，超时没处理、错误码没解析，测试边界条件全挂
李沐阳: 好的我改
（三天后）
周子涵: 改了吗？
李沐阳: PR 提了
周子涵: 我看看...这个 timeout 的处理还是有问题，返回 None 不对
李沐阳: 那你来写？
周子涵: 行，我给你提个 PR
李沐阳: 嗯
```

### 3.3 进度压力冲突

**场景: fork 实现范围争论 (Phase 5)**

```
赵一帆: fork 必须实现 COW，不然没有意义
王思齐: COW 太复杂了，deadline 快到了，先用简化版
赵一帆: 简化版的 fork 不是真正的 fork
王思齐: 能过测试就行嘛
赵一帆: 你这是应付作业
王思齐: 你来写？
陈卓远: 别吵了，fork 用简化版，不实现 COW，有时间再补，先保证其他功能
赵一帆: 好吧
王思齐: 收到
```

## 5. 总群聊消息流设计

### 5.1 总群聊用途

总群聊 (YATSENOS_CHAT_ID) 用于:
- 阶段汇报和总结
- 跨阶段的技术讨论
- 全员通知和公告
- 里程碑庆祝

### 5.2 总群聊消息示例

**阶段汇报**:
```
陈卓远: @所有人 Phase 1 完成情况汇报：
陈卓远: ✅ 内核 ELF 编译配置 - 完成 (林晓薇)
陈卓远: ✅ Bootloader 实现 - 完成 (陈卓远/林晓薇)
陈卓远: ✅ 串口驱动 - 完成 (林晓薇)
陈卓远: ⏳ 调试环境 - 进行中 (周子涵)
陈卓远: 总体进度：85%，预计下周三全部完成
```

**里程碑通知**:
```
张若琳: @所有人 🎉 里程碑达成！
张若琳: Phase 3 进程调度引擎核心功能完成！
张若琳: 已经可以在 QEMU 中创建和切换进程了
张若琳: 感谢大家的努力！
王思齐: 恭喜！
刘劲松: 恭喜！
李沐阳: 恭喜
```

**跨阶段讨论**:
```
赵一帆: 有个问题想讨论一下，fork 的实现需要和内存管理配合
刘劲松: 你说的是栈空间的分配吧？
赵一帆: 对，子进程的栈需要独立分配
刘劲松: 可以用帧分配器来分配，但需要考虑回收问题
陈卓远: 这个放到 Phase 5 再详细讨论，先各自做好当前阶段
```
