## 测试流程

### 步骤一

先检查本地mem-service进程 如果有 关闭所有进程 为了方便测试 缩小检测器时间间隔 更新openclaw.yaml 确保时间间隔被应用 与此同时 开启防抖功能 预防修改被分割 然后重新使用`go build -o bin/mem-service ./cmd/mem-service/main.go`编译mem-service服务 确保编译通过才进行下一步测试

### 步骤二（重要！）

阅读文档白名单的`wiki/NiifwvCvtiPJmrkkegMckNDPnxf`文档内容（文档为空） 参考docs/mock/yatsenos/0x01/task.md中山大学操作系统实验课文档 用实验课作业内容模拟真实的项目开发 在书写模拟项目时 不需要写决策人（因为当前没有多人进行测试 只有一个人 所以不需要加入判断决策人的逻辑） 设计50条带有决策信息的文档修改（40处文档正文修改 10处文档评论）这四十处正文修改不要明显显示出决策性 就像"后端框架: Gin"这样就好 符合开发文档自然写法 理由可写可不写

在这50处文档修改中 需要包含所有决策类型：1. 重复决策 2. 冲突决策（分为llm可自行处理和不可自行处理） 3. 反对意见 4. 正常决策更新 5. 决策回溯（上一次更新完决策之后又回溯到上上次的决策=撤销上次更新 但git里不能覆盖上次更新）

### 步骤三

启动mem-service服务 将日志输出在日志文件里 定时5mins 

### 步骤四

将所有文档修改写成test/lark-doc/text目录下的txt文件 lark-cli在文档里追加修改 逐个插入txt文件

每次加入修改后等待一小段时间 要根据配置文件openclaw.yaml的lark-doc检测间隔来定 观察日志输出 检查日志中有没有正确的调用llm进行决策提取 在短时间内多次插入修改内容防抖机制是否合理运行 多次插入修改内容是否被正确提取成多个决策而不是单个决策里面塞了大量文本（这是无效决策）
